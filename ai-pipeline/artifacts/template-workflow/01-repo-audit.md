## Fragmentation & Issues Found

### 1. One-Source-of-Truth Violation (HIGH)
The PowerShell setup script (`setup-antigravity-template.ps1`) contains **full inline copies** of every template file. If any skill or rule is updated in the repo, the change must also be manually applied inside the PS1 script. This creates a guaranteed drift path.

**Impact**: Template consumers running the script get stale content; contributors face dual-maintenance.

### 2. Cross-Platform Gap (HIGH)
The only bootstrap mechanism is a Windows PowerShell script. Linux/macOS developers (the primary audience for Python/TypeScript work) have no automated setup path.

**Impact**: Manual file copying required on non-Windows systems.

### 3. `01-project-context.md` Ships as Pure Placeholder (MEDIUM)
The committed rule file contains only comments and empty sections. There's no validation or checklist to ensure consumers actually fill it in before use.

**Impact**: Projects bootstrapped from this template may run with a blank context rule, reducing AI assistant quality to near-zero for project-specific questions.

### 4. No Skill for the Agent Workflow System Itself (MEDIUM)
There's no skill to guide the AI through the task of running a meta-analysis or refactor workflow on a project. This limits the template's value for project auditing.

### 5. Docs Are Sparse (LOW)
Only one doc file (`docs/ADDING_SKILLS.md`). No onboarding flow, no architecture overview beyond the README, no runbooks.

### 6. No CI/CD Validation (LOW)
No GitHub Actions to verify that skill files have valid frontmatter, rules have correct activation fields, or docs links are not broken.

---

## Biggest Structural Issue

> **The setup script is the inverse of what it should be.**
>
> Currently: source of truth lives inside the PS1 script (inline here-strings).
> Should be: source of truth lives in the committed files; the setup script *copies* them.
