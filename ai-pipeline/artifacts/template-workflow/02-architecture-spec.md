## Target Architecture

### Principle: Files Are the Source of Truth

The setup script must not contain file content inline. It must reference and copy the actual committed files.

```
Correct flow:
  committed files (SKILL.md, rules/*.md, etc.)
       │
       ▼
  setup.sh / setup.ps1 (copy files to target project)
       │
       ▼
  consumer project (gets exact committed content)
```

### Layer Map

```
Layer 0 — Identity (always loaded)
  GEMINI.md          ← Antigravity-specific overrides
  AGENTS.md          ← Cross-tool baseline

Layer 1 — Context (always loaded, project-specific)
  .agent/rules/01-project-context.md   ← Filled in per project

Layer 2 — Standards (glob-triggered)
  .agent/rules/02-python-standards.md  ← *.py files
  .agent/rules/03-typescript-standards.md ← *.ts/*.tsx files

Layer 3 — Skills (on-demand, semantic)
  .agent/skills/fastapi-dev/
  .agent/skills/react-frontend/
  .agent/skills/testing/
  .agent/skills/homelab-ops/
  .agent/skills/docker-deploy/
  .agent/skills/agent-workflow/   ← NEW: meta-analysis skill

Layer 4 — Bootstrap (one-time)
  setup.sh       ← bash (Linux/macOS)
  setup.ps1      ← PowerShell (Windows)
  Both read from committed files, never duplicate content.

Layer 5 — Agent Workflow System (this system)
  prompts/agents/     ← Agent chain prompts
  docs/agents/        ← Execution order, runbook, README
  ai-pipeline/        ← Artifact outputs from agent runs
```

## Design Decisions

### Decision 1: Keep setup script as a thin copier
Rather than rewrite the PS1 to copy files (which could break existing users who rely on it), add `setup.sh` as the canonical cross-platform path. Document that the PS1 will be migrated to a file-copy pattern in a future iteration.

### Decision 2: Add `agent-workflow` skill
A skill that activates when users want to run a structured analysis, refactor, or audit chain. It references the `prompts/agents/` directory and guides the AI through the workflow steps.

### Decision 3: Add validation checklist to `01-project-context.md`
Add a commented-out `## Completion Checklist` section to the context template so consumers know what must be filled before the template is useful.

### Decision 4: Docs in `docs/agents/`
Follow the existing `docs/` convention. Add `docs/agents/README.md`, `execution-order.md`, and `runbook.md`.
